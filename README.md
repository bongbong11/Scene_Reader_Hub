# 씬판독기 Hub

캐릭터의 성격과 설정을 지키며, 대화·관계·사건이 자연스럽게 이어지도록 돕는 SillyTavern 확장입니다. Jev가 최근 롤플레잉 대화를 판독하고, 다음 답변에 필요한 진행 방향과 인물 기록을 골라 전달합니다.

**Hub 0.2.31 · Jev 서버 플러그인 0.10.3**

실제 이야기는 채팅 모델이 작성합니다. 판독 결과가 전달되어도 모델이 지시를 놓치거나 다르게 표현할 수 있습니다. 씬판독기의 결과 화면에서는 **주입 준비 → 실제 요청 포함 → 답변에서 실행됐는지 확인**을 구분합니다.

이번 자료 정리 기능은 **화면 확장과 서버 플러그인 0.10.3를 함께 업데이트**한 뒤 SillyTavern을 재시작하고 브라우저를 새로고침하세요. 기존 인물 JSON을 다시 만들거나 재임베딩할 필요는 없습니다. 플러그인은 아래 명령어로 덮어쓸 수 있습니다. 자세한 변경 사항은 [업데이트 내역](CHANGELOG.md)을 확인하세요.

## 처음 시작하기

창 맨 위의 **잼 / 긂** 버튼으로 캐릭터 행동 보정을 고릅니다. **잼**은 장황한 설명과 근거 없는 집착·통제·급발진을, **긂**은 성격과 갈등을 무조건 친절·화해로 바꾸는 경향을 줄이도록 돕습니다. 기본값은 긂이며 모든 채팅방에 공통으로 저장됩니다. 선택은 다음 판독부터 적용됩니다. 자동 판독을 껐다면 **지금 판독**을 눌러 주세요.

이 버튼은 캐릭터·NPC의 공통 행동 보정만 바꿉니다. 실제 연결 모델, 인물 기록, 별도로 선택한 갈등·전개 설정은 바뀌지 않습니다. 위브 프리셋 연동을 사용하면 선택한 보정문도 인물 매크로로 함께 전달됩니다. 위브 없이도 사용할 수 있으며, 프리셋의 상세 캐릭터 행동 원칙을 통째로 대체하는 기능은 아닙니다. 같은 보정문을 프리셋에도 중복해서 넣을 필요는 없습니다.

1. 아래 안내에 따라 화면 확장과 서버 플러그인을 설치합니다.
2. 씬판독기의 **톱니바퀴 → 모델·키 설정**에서 공홈 TypeSafe 또는 나노GPT 구독 전용 Jev 키를 저장하고 연결을 확인합니다.
3. **자동 전개**에서 원하는 전개 성향과 사건·인물 확률을 고릅니다. 처음에는 기본값으로 시작해도 됩니다.
4. 인물 설정을 자세히 반영하려면 **인물 판정**에서 분석 명령문을 복사해 외부 AI로 JSON 파일을 만든 뒤 가져와 적용합니다.
5. 고급 전개·갈등용 진행·연속성 추론은 필요한 기능만 켭니다.

## 설치와 업데이트

### 화면 확장

SillyTavern의 **확장 → 확장 설치**에 다음 주소를 입력하세요.

```text
https://github.com/bongbong11/Scene_Reader_Hub.git
```

설치 후 새로고침하면 **실리태번 확장 탭 → 씬판독기**에서 사용 여부와 채팅창 아이콘 표시를 설정할 수 있습니다. **씬판독기 열기**, 채팅 입력창 옆 끼끼 아이콘, 마법봉 메뉴로 창을 엽니다. 아이콘을 숨겨도 기능은 계속 사용할 수 있습니다.

이후에는 SillyTavern 확장 목록의 업데이트 기능으로 갱신하고 새로고침하세요. 파일을 직접 덮어쓰는 경우에는 `src` 폴더를 포함한 확장 전체를 교체해야 합니다.

### 서버 플러그인

**[서버 플러그인 0.10.3 ZIP 다운로드](https://raw.githubusercontent.com/bongbong11/Scene_Reader_Hub/main/downloads/scene-reader-jev-plugin-v0.10.3.zip)**

압축을 직접 풀지 않고 아래 명령으로 설치하거나 업데이트할 수도 있습니다. **SillyTavern을 종료한 뒤, SillyTavern 폴더에서** 해당 명령 한 줄을 실행하세요. Node.js와 curl이 필요합니다. 완료 후에는 SillyTavern을 다시 시작하세요.

**휴대전화 · Termux**

```bash
curl -fL "https://raw.githubusercontent.com/bongbong11/Scene_Reader_Hub/main/downloads/update-scene-reader-plugin.cjs" -o "$TMPDIR/scene-reader-update.cjs" && node "$TMPDIR/scene-reader-update.cjs"
```

**컴퓨터 · Windows CMD**

```bat
curl.exe -fL "https://raw.githubusercontent.com/bongbong11/Scene_Reader_Hub/main/downloads/update-scene-reader-plugin.cjs" -o "%TEMP%\scene-reader-update.cjs" && node "%TEMP%\scene-reader-update.cjs"
```

**맥북 · macOS 터미널**

1. 실행 중인 SillyTavern을 종료합니다. 터미널에서 실행했다면 해당 창에서 **Control + C**를 누르세요.
2. **Command + Space**를 누르고 `터미널`을 검색해 실행합니다.
3. `cd`를 입력하고 **공백을 한 칸** 넣은 뒤, Finder의 **SillyTavern 폴더**를 터미널로 끌어다 놓고 Enter를 누릅니다. `server.js`와 `config.yaml`이 있는 폴더이며, 그 안의 `plugins` 폴더로 들어가는 것이 아닙니다.
4. 아래 명령 한 줄을 붙여넣고 Enter를 누릅니다.

```bash
curl -fL "https://raw.githubusercontent.com/bongbong11/Scene_Reader_Hub/main/downloads/update-scene-reader-plugin.cjs" -o "${TMPDIR:-/tmp}/scene-reader-update.cjs" && node "${TMPDIR:-/tmp}/scene-reader-update.cjs"
```

`Installed Scene Reader plugin ...`이 표시되면 설치가 완료된 것입니다. 처음 설치했다면 같은 폴더의 `config.yaml`에서 `enableServerPlugins: true`로 설정한 뒤, 평소 사용하던 방법으로 SillyTavern을 다시 실행하세요. 브라우저 새로고침만으로는 플러그인이 적용되지 않습니다.

`node: command not found`가 나오면 SillyTavern을 실행할 때 사용하는 Node.js 환경의 터미널에서 실행해야 합니다.

파일을 모두 내려받아 확인한 뒤 해당 플러그인만 교체합니다. 이전 플러그인은 `SillyTavern/backups/scene-reader-plugin`에 보관하며, 키·저장 자료·다른 플러그인은 변경하지 않습니다. 다른 폴더에서 실행해야 한다면 마지막 명령 뒤에 SillyTavern 폴더 경로를 따옴표로 감싸 추가하세요. 처음 설치할 때는 아래의 `enableServerPlugins` 설정도 필요합니다.

ZIP으로 직접 설치하려면:

1. SillyTavern을 완전히 종료합니다.
2. 압축 안의 **scene-reader-jev 폴더 전체**를 SillyTavern의 **plugins** 폴더에 넣습니다. 이미 설치했다면 같은 폴더에 덮어씁니다.
3. SillyTavern의 `config.yaml`에서 다음 설정을 켭니다.
4. 저장한 뒤 SillyTavern을 다시 시작합니다. 브라우저 새로고침만으로는 플러그인이 켜지지 않습니다.

```yaml
enableServerPlugins: true
```

폴더 안에 아래 파일들이 바로 있어야 합니다. ZIP에 들어 있는 나머지 파일과 하위 폴더도 함께 설치하세요.

```text
SillyTavern/plugins/scene-reader-jev/package.json
SillyTavern/plugins/scene-reader-jev/index.cjs
SillyTavern/plugins/scene-reader-jev/storage.cjs
```

화면 확장과 서버 플러그인은 설치 위치가 다릅니다. 휴대전화에서도 **서버가 실행되는 SillyTavern 폴더**에 넣어야 하며, 다운로드만 해서는 설치되지 않습니다. 다른 사람이 운영하는 서버라면 관리자에게 설치를 요청하세요. 기존 사용자 데이터 폴더는 삭제하지 마세요. `enableCorsProxy`는 켤 필요가 없습니다.

직접 다운로드가 되지 않으면 GitHub의 **Code → Download ZIP**으로 저장소를 받은 뒤, 안의 `server-plugin` 폴더를 `scene-reader-jev`로 이름을 바꾸어 위 위치에 넣어도 됩니다.

공유 검색은 같은 장면의 임베딩을 세계관·인물 검색에 재사용합니다. 각 인물의 기록은 따로 고르며, 내용이나 모델이 달라지면 다시 계산합니다. 서버 재시작이나 캐시 만료 뒤에는 새로 계산할 수 있습니다. 지원하지 않는 SillyTavern 환경에서는 기존 검색을 사용하고, 상단 현재 상태에서 검색 방식을 확인할 수 있습니다.

### 기존 씬판독기에서 교체하기

필요한 자료를 백업한 뒤 **기존 화면 확장만 제거**하고 Hub를 설치하세요. 같은 사용자 계정과 같은 캐릭터·그룹 채팅을 열면 기존 설정·인물·세계관·이력·서버 키를 이어서 읽습니다. 기존 확장과 Hub를 동시에 켜지 마세요. 사용자 데이터와 서버 플러그인은 유지해야 합니다.

아주 오래된 씬판독기 **0.16.3 이하**에서 만든 인물 규칙은 현재 분석 명령문으로 다시 추출해야 합니다. 이미 현재 형식의 JSON을 사용 중이라면 이번 업데이트를 위해 다시 만들 필요는 없습니다.

## 모델과 키 설정

**톱니바퀴 → 모델·키 설정**에서 설정합니다. 세 항목의 용도가 다릅니다.

| 항목 | 용도 | 설정 방법 |
| --- | --- | --- |
| Jev 판독 | 장면·진행·인물 기록 판독 | **공홈 TypeSafe / 나노GPT 구독 전용** 선택 → 키 저장 → 연결 확인 |
| 확장 연결모델 | 선택 기능인 연속성 추론·감정 수집, 세계관 설명 생성 | SillyTavern에 저장한 연결 프로필 선택 |
| 임베딩 모델·키 선택 | 인물·세계관 기록에서 관련 후보 검색 | 사용할 임베딩 서비스 선택 → 필요한 인증 설정 → 연결 확인 |

Jev 판독은 TypeSafe 공홈 또는 나노GPT 구독 전용 연결을 선택합니다. 두 키는 따로 보관되며 기존 공홈 키도 유지됩니다. 확장 연결모델을 쓰려면 SillyTavern의 API 연결 메뉴에서 프로필을 저장하고 Hub에서 선택하세요. 목록에 없으면 **프로필 새로고침**을 누릅니다. 이미 완성된 인물·세계관 JSON을 가져오는 데에는 연결 프로필이 필요하지 않습니다.

공홈 TypeSafe는 **최신 자동 / Jev 1.14 / Jev 1.13** 중 선택할 수 있습니다. 최신 자동은 제공사가 정한 버전을 따르며, 1.14·1.13은 해당 버전으로 고정합니다. 공홈에서 선택한 버전과 나노GPT에서 선택한 버전은 각각 저장됩니다.

### 나노GPT 구독으로 Jev 사용하기

서버 플러그인 **0.10.3**로 업데이트하고 SillyTavern을 재시작한 뒤 설정하세요.

1. [나노GPT API 키 관리](https://nano-gpt.com/api)에서 사용할 키의 Billing을 **Subscription only**로 설정합니다.
2. Hub의 **Jev 판독 → 나노GPT · 구독 전용**을 선택합니다.
3. **Jev 1.14**(모델 ID `typesafe/jev-1.14`) 또는 **Jev 1.13**(`typesafe/jev-1.13`)을 선택합니다.
4. 나노GPT 키를 입력하고 **키 저장**을 누릅니다. 구독 전용 설정과 실제 판독 응답을 확인한 뒤 서버에 저장합니다.

키 저장과 연결 확인은 짧은 시험 질문을 보내므로 나노GPT 사용량에 잡힐 수 있습니다. 시험 응답을 읽지 못하면 키를 저장하지 않고 오류를 표시합니다. 사용량 기록만으로 연결 성공을 의미하지는 않습니다.

연결프로필을 만들 필요는 없습니다. 일반 채팅 요청 대신 Jev 전용 질문 형식으로 호출합니다. 구독이 만료됐거나 사용량이 소진됐거나 해당 모델을 구독으로 사용할 수 없으면 오류를 알리고 멈춥니다. 다른 유료 경로로 재시도하지 않습니다. 키를 빈칸으로 저장하면 나노GPT 키만 삭제합니다.

나노GPT의 구독 주소 자체는 잔액 과금을 막지 않으므로 **Subscription only 설정이 반드시 필요합니다.** Hub는 매 호출 전 키의 잔액 사용 차단 상태를 확인합니다. [공식 과금 설정 안내](https://docs.nano-gpt.com/api-reference/miscellaneous/billing-override#api-key-billing-settings)

### 임베딩 연결

- **Gemini · AI Studio:** AI Studio를 선택하고 해당 키를 저장합니다.
- **Gemini · Vertex AI:** Vertex AI를 선택합니다. Express 키는 새 키 입력란에 넣고, 서비스 계정 JSON은 SillyTavern 연결 설정에서 등록합니다. 리전은 `global`로 고정됩니다.
- **NanoGPT Qwen:** 해당 서비스의 키를 저장합니다.
- **SillyTavern 로컬:** API 키 없이 서버의 내장 임베딩을 사용합니다. 처음에는 모델 다운로드·준비로 시간이 걸릴 수 있으며 속도는 실행 환경에 따라 달라집니다.

Gemini 임베딩 모델은 자동으로 설정됩니다. 선택한 서비스에 인증 정보가 저장되어 있다면 다시 입력하지 않아도 됩니다. **키 저장됨**은 저장 여부를 뜻하므로, 사용 가능 여부는 **연결 확인**으로 확인하세요. 임베딩을 완전히 끄는 설정은 없습니다.

임베딩 키는 SillyTavern의 공용 키 저장소를 사용합니다. 같은 서비스의 키를 쓰는 다른 기능에도 영향을 줄 수 있습니다. 외부 임베딩 서비스를 선택하면 검색에 필요한 판독 기록과 최근 장면 일부가 해당 서비스로 전달됩니다.

### 임베딩 재시도

판독에서 실제로 검색할 자료의 임베딩을 먼저 확인합니다. 정상 기록은 재사용하고, 누락되거나 바뀐 기록만 생성한 뒤 저장을 확인하고 검색·판독을 이어갑니다. 처음 쓰는 큰 자료는 준비 시간이 걸릴 수 있습니다. 준비·저장 확인에 실패하면 이번 판독을 중단하며, 재시도하면 완료된 부분은 재사용합니다. 정상 색인의 검색 요청만 실패한 경우에는 기존 글자·내용 매칭을 사용할 수 있습니다.

창 위의 **임베딩 재시도**는 현재 방에 등록된 인물과 선택한 세계관의 검색 자료를 확인합니다. 정상 자료는 재사용하고 누락·실패한 부분을 준비합니다. 전체를 다시 계산해야 할 때만 설정의 **전체 임베딩 다시 만들기**를 사용하세요.

재시도는 원본 인물·세계관을 삭제하거나 판독을 실행하지 않습니다. 준비가 끝나면 **지금 판독**을 누르세요. 검색 서비스를 바꿔도 원본 JSON을 다시 만들 필요는 없습니다.

## 자동 전개

현재 입력과 최근 대화를 바탕으로 다음 답변의 대화·감정·행동 방향을 고릅니다. 고급 전개를 끈 상태에서도 사용할 수 있습니다.

| 설정 | 조절하는 내용 |
| --- | --- |
| 세계 반응 | 주변 상황이 인물과 행동에 반응하는 방향 |
| 관계 방향 | 인물이 사용자에게 보이는 기본 태도. 실제 시트와 대화도 함께 참고 |
| 기본 전개 성향 | 정적: 관계·감정·대화 중심 / 균형: 대화와 행동을 섞음 / 동적: 행동과 주변 반응을 적극 활용 |
| 관계 진전 속도 | 가까워짐·거리 두기·갈등 등 관계가 변하는 폭 |
| 사건 해결 속도 | 진행 중인 문제를 해결에 얼마나 접근시킬지 |
| 육체적 진행 단계 | 극도의 슬로우번·느리게·중간·빠르게·무절제 중 선택 |

정적이라고 진행을 멈추지는 않습니다. 동적은 행동이 늘어 체감 속도가 빨라질 수 있지만, 관계 진전과 사건 해결 속도는 따로 조절할 수 있습니다. 글의 길이·장르·문체는 채팅 모델과 프리셋을 따릅니다.

육체적 진행은 감정 퍼센트를 직접 바꾸는 설정이 아닙니다. 인물 판정과 함께 사용하며, 페르소나는 유저 사칭 허용을 켠 경우에만 포함합니다. NPC의 충동 관련 판독은 인물별로 선택합니다. 느린 단계를 골랐다고 문맥에 맞는 신체 명칭·욕설·성인 농담 같은 단어 표현 자체를 금지하지는 않습니다.

### 새 사건·인물 생성과 돌발

**새 사건·인물 생성**을 켜면 각각의 확률을 사용합니다. 끄면 두 새 생성을 모두 중단하지만, 기존 인물의 행동·현재 상호작용·진행 중인 사건은 유지됩니다.

- **사건 확률:** 0% · 끄기 / 18% / 35% / 58% / 75%
- **인물 확률:** 0% · 끄기 / 5% / 10% / 20% / 35% / 50% / 75% / 100%

**돌발 추가**는 끄기·사건·인물·둘 다 중에서 고릅니다. 발생 확률을 높이는 기능이 아니라, 복선 없이도 장면에 맞는 새 전개를 허용하는 선택입니다. 돌발을 꺼도 일반 생성 확률은 작동하며, 사건만 선택했다고 일반 인물 생성까지 꺼지지는 않습니다.

사건과 인물은 각각 한 번 추첨합니다. 일반·돌발·고급 사건을 중복 추첨하지 않으며, 같은 응답의 재판독·리롤·새로고침도 같은 추첨을 사용합니다. **0%**는 해당 새 생성만 끕니다. 기존 인물의 재등장에는 새 인물 추첨을 적용하지 않습니다.

한 응답에는 새 사건 하나와 새 인물 하나까지 제안합니다. 세계 능동성을 켠 경우 새 인물이 장면에 맞는 일행이나 집단일 수도 있습니다. 100%는 추첨 통과를 뜻하며, 불가능한 접근이나 설정 충돌을 무시하거나 실제 모델의 등장을 보장하지는 않습니다. 결과에서 선택·제외 이유를 확인할 수 있습니다.

### 세계 능동성

기본 전개 성향 아래 **세계 능동성**을 켜면 인물이 성격과 목적에 맞게 먼저 말하고 행동하도록 돕습니다. 짜증·거절·장난·대립을 모두 친절로 바꾸지 않고, 주변 인물도 배경 활동·짧은 역할·직접 참여로 나누어 움직일 수 있습니다. 몸싸움이 어울리는 상황은 위협이나 속마음에만 머물지 않도록 안내합니다.

모든 장면에 사람이나 싸움을 추가하지는 않습니다. **균형·동적**에서는 완성된 답변이 3회 연속 정체로 판독되면 현재 대화·선택·행동을 한 단계 진행하도록 보강합니다. 조용한 감정 변화도 진행으로 보며, 필요한 대기나 사용자의 선택을 재촉하지 않습니다. **정적**에서는 이 보강을 사용하지 않습니다.

### 지금 판독과 결과

**지금 판독**을 누르면 입력창의 RP 초안과 최근 대화를 읽습니다. **이번 턴 최종 적용**에서 선택된 진행을 보고, 아래에서 사건·인물·상세 판정을 확인하세요.

**검증 대기**는 실제 답변에서 실행됐는지 아직 확인하지 않았다는 뜻입니다. 선택한 계획을 이미 일어난 사실로 저장하지 않습니다. **사건 끝내기**는 확장이 추적하는 사건을 정리하며, 실제 채팅을 고치지 않습니다.

## 고급 전개와 갈등용 진행

### 고급 전개

**고급 전개 사용**을 켜고 관계·치정, 일상·교류, 탐험·발견 등 원하는 요소를 고릅니다. 선택한 요소는 새 사건뿐 아니라 평소 대화·선택·인물 행동에도 반영됩니다. 여러 요소를 골라도 현재 장면에 맞는 방향을 중심으로 움직이며, 모든 요소를 매번 실행하지는 않습니다. 요소를 전부 해제하면 별도 방향을 덧붙이지 않습니다.

기본 전개 성향과 관계·해결 속도도 함께 적용됩니다. 문체·서술 방식은 기존 프리셋을 따릅니다. 새 고급 사건은 자동 전개의 사건 확률을 사용하지만, 기존 인물의 활동과 진행 중인 사건에는 다시 추첨하지 않습니다. **새 사건·인물 생성 OFF 또는 0%**여도 기존 경쟁자의 접근·요구·방해 같은 행동은 가능하며, 별개의 새 사건이나 새 인물을 추가하는 것은 제한됩니다.

사람이 필요한 고급 사건은 관련된 **등록 NPC 기록 → 이미 등장했던 인물 → 생성이 허용된 새 인물** 순으로 담당 인물을 찾도록 판독합니다. 등록 NPC는 최근 대화에 이름이 없어도 등장·연락 후보가 될 수 있습니다. 새 인물을 만드는 경우에만 새 인물 확률이 필요합니다.

새 사건이 없는 평소 진행에서도 관련 등록 NPC나 이미 알려진 인물이 자기 목적에 따라 움직일 수 있습니다. 인물 판정을 끄면 등록 JSON을 검색하지 않고, 판독에 제공된 대화와 기존 인물 정보만 사용합니다.

선택된 인물은 실제 말·연락·요구·방해 등의 행동을 하도록 안내합니다. 속마음만으로 실행을 대신하지 않으며, 성격에 맞지 않는 적대 행동이나 상대방의 반응을 미리 확정하지 않습니다. 결과의 **전개 방향**과 **행동 담당 인물**에서 이번 방향과 준비·요청 포함 상태를 확인하고, 실제 행동 여부는 다음 판독에서 확인합니다.

### 갈등용 진행

싸움 유지·빌런·NPC의 자율적인 반응·세계 적대성 등 필요한 항목만 켜세요. **부정 편향을 최우선으로 사용**은 이 탭에서 켠 방향을 우선하도록 합니다. 인물의 성격·관계·지식은 함께 유지합니다. 모든 일반 NPC를 악역으로 바꾸거나, 갈등이 없는 장면을 무조건 싸움으로 만드는 설정은 아닙니다.

## 세계관

**자동 전개**에서 사용할 세계관을 고릅니다. 목록은 같은 사용자 계정의 확장 전체에서 공유하며, 고급 전개를 꺼도 세계관을 사용할 수 있습니다.

### 일반 세계관

**고급 전개 → 세계관 관리 → ＋**에서 이름과 원문을 넣습니다. 짧은 세계관 설명을 직접 적으면 모델 호출 없이 저장합니다. 비워 두면 확장 연결모델이 원문을 읽고 설명을 만듭니다. 저장 후 자동 전개에서 해당 세계관을 선택하세요. 일반 세계관은 원문 전체를 전달합니다.

**원작·프랜차이즈 세계**는 장소·시대·역할에 맞는 원작 인물을 후보로 고려하는 설정입니다. 유명 인물을 무조건 등장시키지는 않습니다.

### 고급 세계관 JSON

긴 원문에서 필요한 규칙만 골라 쓰려면 **세계관 관리 → 고급 세계관 추가**를 사용하세요.

1. **분석 명령문 복사**를 눌러 외부 AI에 전달합니다. 원문이 선택되어 있으면 함께 복사됩니다. 없으면 기본 명령문만 복사되므로 원문을 따로 함께 주세요.
2. 결과를 JSON 파일로 받아 가져오거나 JSON 입력란에 붙여 넣습니다.
3. 미리보기를 확인하고 **검증 후 저장**을 누릅니다.
4. 자동 전개에서 저장한 세계관을 선택합니다.

고급 세계관은 **고정 규칙**과 장면에 맞는 **장면별 규칙**을 전달합니다. 장면별 판독이 실패해도 고정 규칙은 유지하며 오류를 안내합니다. 세계관의 사실을 모든 인물이 아는 정보로 취급하지 않습니다. 일반 세계관 원문이 자동으로 이 형식으로 바뀌지는 않습니다.

### 추가 참고

**자동 전개 → 현재 세계관 → 추가 참고**를 펼쳐 미국·영국·한국의 공휴일·행사, 미국·영국 대학, 대학·프로 미식축구, **호그와트 학사·행사**를 각각 선택하세요. 해당 날짜와 월에 어울리는 재료만 전달하며, 행사·경기·등장을 반드시 진행시키지는 않습니다. 학교·팀·이야기에서 정한 일정이 우선합니다.

대학은 개강 준비·수업·평가·방학을, 미식축구는 비시즌·훈련·캠프·정규시즌·포스트시즌을 구분합니다. 대학 선수의 프로 진출 준비도 시기에 맞는 참고 재료에 포함하지만, 지명·계약·데뷔를 확정하지 않습니다. 기본 대학 세계관에는 해당 월의 학사 자료가 연결됩니다. **호그와트 학사·행사는 체크했을 때만** 해당 월의 참고 자료를 추가합니다. 해리포터 세계관을 골랐다는 이유만으로 켜지지 않으며, 기존 세계관 내용은 교체하거나 삭제하지 않습니다.

**날짜 확인 방법**

1. 처음 사용할 때 최신 RP에서 찾은 날짜를 확인하는 창이 뜹니다. 현재 장면 날짜가 맞으면 **맞아요**를 누르세요. 여러 날짜가 있거나 월·일 순서가 모호하면 알맞은 항목을 고릅니다.
2. 이후에는 확인한 항목의 날짜를 읽습니다. 매번 확인하거나 모델을 추가로 호출하지 않습니다.
3. **나중에**를 누르면 일반 판독은 계속되고, 날짜 확인 전까지 시즌 참고만 쉽니다. **추가 참고**의 선택지 아래 **날짜 확인**으로 다시 열 수 있습니다.
4. 프리셋을 바꾸면 새 프리셋으로 받은 답변에서 날짜 형식을 다시 확인합니다. 날짜가 없거나 형식이 바뀌어 읽을 수 없으면 임의로 추측해 주입하지 않습니다.

공휴일은 반복되는 일반 일정을 참고합니다. 지역별 휴일·학교별 학사일정·해당 연도 경기 일정이나 임시공휴일을 모두 조회하는 기능은 아닙니다. 한국 음력 명절은 1900~2050년 범위에서 계산하며, 연도를 모르면 연도 계산이 필요한 날짜는 제외합니다.

이전의 통합 **시즌 행사** 선택은 삭제되었습니다. 필요한 국가를 새로 선택해 주세요. 옛 선택값과 사용이 종료된 일부 설정은 자료를 불러오거나 복원할 때 정리하며, 인물·세계관 파일과 백업 원본은 삭제하지 않습니다.

## 인물 판정

캐릭터·페르소나·NPC의 시트와 필요한 로어북을 판독 JSON으로 저장한 뒤, 매 장면에 필요한 기록을 골라 사용합니다. SillyTavern의 원본 캐릭터 카드를 대체하지 않습니다.

### 파일 만들기와 적용

1. **인물 판정 → ＋ 캐릭터 / ＋ 페르소나 / ＋ NPC**를 누릅니다.
2. 캐릭터·페르소나는 **시트 가져오기**를 누릅니다. 캐릭터는 설명과 성격 요약을 함께 읽습니다. 가져온 원문은 **시트 확인하기**로 볼 수 있습니다.
3. 필요하면 **연결 로어북 엔트리 고르기**에서 해당 인물의 자료만 선택합니다. NPC는 **시트 서식 복사**로 원문을 작성하거나 한 명 기준의 NPC 로어북 엔트리를 선택하고, 양면·선역·악역 역할을 고릅니다.
4. **분석 명령문 복사**로 외부 AI에 전달합니다. 시트와 선택한 자료가 있으면 함께 복사됩니다. 자료 없이 기본 명령문만 복사할 수도 있으며, 이때는 외부 AI에 원문을 따로 함께 주세요.
5. 받은 **JSON 파일을 업로드**하고 미리보기를 확인한 뒤 **검증 후 저장·적용**을 누릅니다.

복사한 명령문에는 필요한 JSON 구조와 작성 규칙이 포함됩니다. 일반 요약 JSON과 형식이 다르므로 명령문 전체를 사용하세요. 필수 내용이 빠졌거나 파일이 잘리면 저장하지 않고 기존 정상 기록을 유지합니다. 저장 오류가 나면 팝업의 **오류 로그 복사**를 사용할 수 있습니다.

카드 하나에 여러 인물이 있다면 **＋ 캐릭터 → 다인 캐릭터**에서 2~6명을 지정해 JSON 파일 하나로 받으세요. 저장 목록에는 **묶음 이름 → 각 인물 → 날짜별 파일**로 표시됩니다. 같은 카드에 있어도 참여 여부와 필요한 기록은 인물별로 판독합니다.

### 파일 추가·교체·삭제

**저장된 인물 기록**의 최상단 이름 줄에서 **＋ 파일**을 누르면 같은 인물 아래에 새 날짜의 JSON을 추가할 수 있습니다. 이름 표기가 조금 달라도 선택한 인물에 연결합니다. 묶음이라면 대상 인물을 먼저 고르세요.

현재 사용하는 파일에는 **✓ 적용 중**이 표시됩니다. 다른 날짜의 **적용**을 누르면 그 파일로 바뀝니다. **보기**로 해당 날짜의 원문과 판독 기록을 확인하고, **수정**으로 새 JSON을 올려 새 날짜 버전으로 저장할 수 있습니다.

날짜별 **삭제**는 해당 파일만 지웁니다. 적용 중인 파일을 삭제하면 적용도 해제됩니다. 이름 옆 **인물 삭제**는 그 인물과 저장본을 함께 정리하며, 같은 묶음의 다른 인물과 백업은 유지합니다.

### 주입량과 참여 판정

**이번 턴 인물 판정**에서 선택된 기록과 제외 이유를 확인합니다. 장면에 참여 중인 인물의 기록을 사용하고, 고급 사건의 등장 후보는 실제 참여 여부와 따로 다룹니다. 후보로 골랐다는 이유만으로 감정이나 이미 등장했다는 사실을 저장하지 않습니다.

**등록 NPC의 추가 참고 자료는 먼저 짧은 소개로 고릅니다.** 적용 중인 JSON의 역할·관계 등을 참고해 이번 전개와 관련된 파일만 상세 검색합니다. 현재 참여 중인 인물은 기존처럼 다루며, 캐릭터·페르소나의 검색 방식은 유지합니다. 소개가 부족하거나 선별 응답을 확인할 수 없으면 기존 검색 방식으로 처리합니다.

소개는 확장이 자동으로 준비합니다. 기존 JSON을 다시 만들거나 전체 임베딩을 재생성할 필요는 없으며, 적용 파일을 바꾸면 그 파일의 정보를 사용합니다. 파일 선별은 등장인원 제한이 아닙니다. 지정된 중요 인물을 반영하면서 프리셋과 상황에 맞는 다른 인물도 함께 참여할 수 있습니다. 새 중요 인물의 생성은 기존 확률 설정을 따릅니다.

| 캐릭터·페르소나 주입량 | 인물별 기록 상한 | 전체 인물 글자 한도 |
| --- | ---: | ---: |
| 기본 | 4개 | 3,000자 |
| 넉넉하게 · 기본값 | 6개 | 5,000자 |
| 상세하게 | 8개 | 8,000자 |

NPC는 별도로 **간결하게 2개 / 기본 3개 / 넉넉하게 4개**를 고릅니다. 전체 글자 한도는 모든 인물이 함께 사용하므로 항상 상한까지 채우지는 않습니다. 경계·지식 제한도 참고하며, 길이를 넘는 기록은 문장 중간을 자르지 않고 제외합니다. 갈등·세계관 주입은 이 한도와 별개입니다.

페르소나의 행동·대사는 **이 채팅에서 유저 사칭 허용**을 켰을 때만 판독 대상에 포함됩니다. 페르소나의 비밀을 다른 인물의 지식으로 자동 전달하지 않습니다.

### 감정값과 빠진 감정 수집

이번 턴 인물 판정에서 이름을 펼치고 **판정 / 감정값**을 전환하세요. 감정은 막대와 퍼센트로 표시하며 모델이 해석한 참고값입니다.

- **확장 연결모델로 감정 판정 꺼짐:** 롤플 모델이 답변과 함께 상태를 만듭니다. 스트리밍을 끄고 한 번에 응답 하나를 받는 설정에서 사용하세요.
- **켜짐:** 선택한 확장 연결모델이 완성된 답변과 앞선 RP 2턴·현재 입력을 참고합니다. 별도 호출이 발생하며 롤플 답변과 다음 판독은 수집 완료를 기다리지 않습니다. 완료된 값은 이후 판독부터 참고합니다.

**빠진 감정 수집**은 자동 수집 방식과 관계없이 연결 프로필 모델로 누락된 인물·항목만 보충합니다. 저장된 값은 바꾸지 않으며 **0%도 정상 값**입니다. 모두 있거나 같은 답변을 수집 중이면 중복 호출하지 않습니다.

최근 RP 답변 12개와 그 안의 스와이프별 감정값을 보관합니다. 선택한 답변의 값만 사용하며, 스와이프를 바꾸는 것만으로 다시 호출하지 않습니다. 답변을 수정하면 해당 값은 비워지므로 필요할 때 수집 버튼을 누르세요.

NPC의 **성적 충동·자제력 추가 판독**은 인물별로 켭니다. 일반 감정 수집과는 별개이며 기본값은 꺼짐입니다. 문자·통화로 실제 대화에 참여한 인물도 대상이 될 수 있지만, 생각에만 등장한 인물의 감정을 만들어 넣지는 않습니다. 친밀한 장면에서 진행 개입을 쉬는 동안에는 감정 수집도 쉽니다.

## 연속성과 저장되는 진행 상태

씬판독기는 방별로 관계 진행, 진행 중인 사건, 생성한 인물, 직전 감정 등을 저장해 다음 판독에서 참고합니다.

**톱니바퀴 → 모델·키 설정 → 연속성 추론 사용**을 켜고 연결 프로필을 선택하면 완성된 RP 답변마다 **현재 상황**과 **남은 여파**를 짧게 갱신합니다. 지금 누가 어떤 상호작용을 하고 있으며 이전 말·행동의 어떤 영향이 남았는지 다음 판독에 전달합니다. 기존 맥락을 갱신하므로 매번 기록을 덧붙이지 않습니다. 롤플 생성은 분석 완료를 기다리지 않으며, 완료된 분석은 다음 판독부터 사용합니다.

연결모델 호출에 실패하거나 응답을 읽을 수 없으면 실패 단계와 원인 코드를 표시하고 기존의 유효한 맥락을 보존합니다. 두 항목 중 하나만 읽혔으면 해당 항목을 반영하고 나머지는 보존합니다. 빈 문자열은 그 항목에 남길 내용이 없다는 뜻이며, 응답 누락과 구분합니다. 미처리 구간은 다음 분석에 다시 포함하고 오류 직후에는 재호출을 잠시 유예합니다.

약속·일정의 별도 추적, 후속 행동 후보 수집, 소재 편중 지침은 연속성 추론에서 사용하지 않습니다. 다음 행동은 자동 전개가 담당하며 인물별 지식과 감정 수집은 각각 유지합니다. 연속성 수집은 최근 채팅 범위 선택과 별개이며, 감정 수집을 켜는 것만으로 연속성 추론이 켜지지는 않습니다.

숨김·수정·삭제·리롤로 근거가 바뀌면 해당 맥락을 현재 보이는 대화에 맞게 확인합니다. 주입문에는 롤플에 필요한 짧은 내용만 전달하고 원문 번호·해시·수정 이력은 관리용 저장 자료에 둡니다.

이는 장기 기억 확장이나 전체 채팅 요약을 대체하지 않습니다. 관계 누적은 채팅 전체 중심이며 모든 인물 쌍의 관계를 각각 추적하지는 않습니다. 인물의 기본 설정은 적용한 JSON을 기준으로 하므로, 바꾸려면 새 파일을 만들어 적용하세요.

## 공통 설정과 주입 위치

설정 탭의 주입 위치·자동 판독·모델 연결은 모든 방에서 공통으로 유지합니다. 자동 전개 탭의 선택과 인물 주입량 등 **현재 채팅**으로 표시된 항목은 방별로 저장합니다.

**씬판독기 전체 사용**을 끄면 판독과 주입을 중단하고 자료는 유지합니다. **생성 직전에 자동 판독**만 끄면 필요할 때 **지금 판독**을 눌러야 합니다. 입력이나 설정이 달라졌다면 다시 판독하세요.

최근 채팅 범위는 **1~5턴, 기본 3턴**입니다. 현재 입력도 한 턴으로 세므로 1턴에서는 직전 답변이 빠질 수 있습니다. 앞뒤 흐름을 보려면 2턴 이상을 선택하세요. **화면에 확신도 표시**는 표시만 바꾸며 실제 판정이나 등장 확률을 바꾸지 않습니다.

주입은 모델이 답변할 때 참고할 내용을 요청에 함께 보내는 것입니다. 별도 채팅 메시지를 추가하지 않습니다. 기본은 **깊이 0 · system**이며, Chat Completion에서는 **프리셋 항목 앞·뒤**도 선택할 수 있습니다.

- **기본 판정·전개 주입:** 진행과 인물 기준
- **세계관 규칙·시즌 참고 주입:** 세계관과 추가 참고

두 위치는 따로 선택하며 같은 위치로 지정해도 됩니다. 프리셋 위치를 선택한 내용은 기본 위치에 중복 주입하지 않습니다. 기준 프롬프트가 없거나 꺼져 있으면 다른 곳에 임의로 넣지 않고 확인 필요로 표시합니다. 프리셋을 바꿨다면 **프리셋 목록 새로 읽기**로 기준을 확인하세요.

이전 `{{scene-reader}}`, `{{scene-reader-world}}` 매크로는 사용하지 않습니다. 이전 매크로 설정에서 넘어왔다면 기준 프롬프트와 앞·뒤를 다시 확인하세요. **이전 임시 주입 정리**는 Hub의 임시 주입만 정리하며 저장된 프리셋과 자료는 삭제하지 않습니다.


### 위브 프리셋 연동

설정의 **위브 프리셋 연동**을 펼치고 **인물 분석을 매크로로 전달**을 켜세요. 개발자 모드 해제는 필요하지 않습니다. `{{scene-reader-character}}`를 복사해 위브 프리셋의 캐시트 아웃렛 자리에 넣으면, 그 위치로 씬판독기의 인물 분석을 전달합니다.

등록 캐릭터·페르소나·NPC의 선택된 기록뿐 아니라 관계 방향·변화, 인물의 독립적인 판단, NPC의 역할·지식·태도, 감정·갈등 유지와 인물별 연속성 지침을 함께 전달합니다. 이번 판독에서 사용하지 않은 지침을 새로 켜지는 않습니다. 사건의 다음 행동·등장·장면 진행·세계관 지시는 기존 위치에 남으며, 옮긴 지침은 두 위치에 중복해서 넣지 않습니다.

기본값은 꺼짐입니다. 매크로를 넣지 않았거나 지원하지 않는 연결을 사용하면 기존 통합 주입으로 작동합니다. 여러 곳에 넣어도 한 곳에만 전달하며, 별도 모델 호출은 추가하지 않습니다. 과거 판독 결과에는 분리 자료가 없을 수 있으므로, 처음 사용할 때는 새로 판독하세요.

매크로 옵션 옆 **전송 내용 보기**를 누르면 마지막 전송 요청에서 확인한 인물 분석을 팝업으로 볼 수 있습니다. **매크로 반영 확인 / 매크로 미사용·기존 위치로 전달 / 확인 실패**를 구분하며, 준비만 된 내용은 전송 성공으로 표시하지 않습니다. 새 판독·재생성·취소·방 이동 시 이전 확인 내용을 비우고, 새로고침 후에도 남겨두지 않습니다. 모델이 실제 답변에 지침을 반영했는지는 별도로 확인하세요.


## 자료 이사·이어하기·백업

### 자료 이사와 새 채팅

이전 저장 형식의 자료가 있으면 헤더 아래 **📦 자료 이사**를 누르세요. 먼저 백업하고 새 형식으로 옮긴 뒤 확인합니다. 중단되면 다시 눌러 이어갈 수 있습니다. 완료 후 이전 파일 정리를 선택할 수 있으며, 이사가 끝난 자료에 대해 버튼이 반복해서 나타나지 않습니다.

설정의 **이야기 연결**에서 자료를 가져올 이야기를 고른 뒤 **이어가기 / 새 이야기 시작**을 선택합니다. 이어하기는 사건·관계·상태와 이전 방의 최신 전개 선택을 가져옵니다. 새 이야기는 공통 인물 자료와 기본 전개 선택으로 시작합니다. 이전 방의 기록은 따로 남습니다. 기존 방을 연결하려면 설정의 **이 방 자료 연결**을 사용하세요. 이미 연결된 방에서 **현재 진행에서 분기**를 선택하면 그 시점까지의 상태를 가지고 별개로 진행합니다. **이전 파일 정리**에는 옛 브라우저 세계관 가져오기와 이관 전 파일 삭제가 모여 있습니다.

인물 JSON은 파일당 최대 **128 MiB**까지 가져올 수 있습니다. 내부에서 나누어 저장하고 필요한 부분을 읽으며, 미리보기는 50개씩 표시합니다. 세계관 목록은 방과 관계없이 계정 안에서 공유합니다.

### 백업 범위와 목록

**지금 백업**은 같은 사용자 계정의 **모든 방 자료와 공통 설정**을 독립된 백업으로 보관합니다. 평소 저장할 때마다 백업을 만들지는 않습니다.

방 안에서는 기본적으로 그 방의 백업만 표시합니다. 가져온 채팅방의 ID가 달라졌다면 목록 범위를 **같은 캐릭터의 이전 백업**으로 바꿔 찾으세요. 방을 열지 않은 상태에서는 이름 없는 이전 백업을 포함한 전체 목록이 보입니다. 백업 이름은 백업을 만든 캐릭터·채팅방 기준입니다.

**복원 → 원본 방 선택 → 이 방으로 복원**하면 선택한 방의 인물·진행·금고 자료를 현재 방에 가져옵니다. 다른 방과 공통 설정은 유지합니다. 같은 캐릭터라면 방 ID가 달라도 복구할 수 있습니다. 캐릭터 식별자가 달라졌거나 확인되지 않으면 가져올 자료가 맞는지 한 번 확인합니다. **모든 방을 함께 복원**을 펼쳐 선택하면 모든 방 자료와 공통 설정이 백업 시점으로 돌아갑니다. 복원 직전 상태도 별도로 백업합니다.

원본 채팅방을 삭제했어도 백업 안의 자료를 선택할 수 있습니다. 옛 백업에 방 이름이 없으면 **인물 이름과 보관 파일 수**를 보고 고르세요. 백업을 만든 방이 확인되지 않을 때는 직접 선택해야 합니다. 파일이 0개인 자료를 선택하면 인물 파일은 복원되지 않습니다.

**다운로드**로 `.srbackup` 파일을 보관하고 **백업 가져오기**로 전체 복원합니다. 이전 JSON 백업도 가져올 수 있습니다. **인물만 내보내기**에서는 전체 백업에 포함된 여러 방의 인물 중 필요한 JSON만 선택해 받을 수 있습니다. 서버 백업에는 키가 보관되지만 다운로드 파일에는 API 키와 전용 원문이 포함되지 않습니다.

백업 옆 **삭제**는 해당 백업 파일을 지웁니다. 현재 사용 중인 인물·이야기 자료는 지우지 않습니다. 오래된 자동 백업도 이 목록에서 정리할 수 있습니다.

### 자료 정리

정리 완료 후에도 `chunks`와 `operations` 폴더에는 사용 중인 자료와 최근 재시도 기록이 남습니다. 폴더가 비어야 정상인 것은 아닙니다.

**설정 → 자료 정리**에서 관리합니다. 작은 **버튼 설명**을 펼치면 각 기능과 남기는 자료를 확인할 수 있습니다.

- **저장 파일 정리:** 자동·수동 방식을 선택합니다. 자동은 저장 요청이 없는 동안 정리하고, 수동은 **지금 정리**를 눌렀을 때 실행합니다. 현재 캐릭터의 쓰지 않는 이전 자료와 어느 방에서도 참조하지 않는 저장 조각·완료 작업을 지웁니다. 다른 방의 자료, 이어가기·리롤에 필요한 기록, 등록한 날짜별 인물 파일과 백업은 유지합니다. 삭제한 파일 수와 확보한 용량을 표시합니다.
- **방 자료 삭제…:** 같은 캐릭터의 저장된 방 중 정리할 방을 고릅니다. 삭제 전에 복원 가능한 백업을 만들고, 선택한 방의 확장 자료를 삭제합니다. 다른 방에서 함께 쓰는 이야기 자료와 실리태번 대화는 남깁니다.
- **진단 기록 비우기:** 현재 화면에 쌓인 실행 기록과 지난 오류 기록을 비웁니다. 판독 상태·관계·리롤 기록이나 해결되지 않은 현재 오류 안내는 지우지 않습니다.
- **채팅의 옛 확장 정보 정리:** 서버로 이관되어 화면에서 제거된 옛 씬판독기 정보를 채팅 파일에도 반영합니다. 대화 본문과 다른 확장의 기록은 삭제하지 않습니다.
- **이전 파일 정리:** 자료 이사가 끝난 옛 저장 파일을 삭제하거나, 브라우저의 옛 추가 세계관을 가져옵니다.

실리태번에서 일반 캐릭터 채팅을 삭제하면, 확장에 저장된 방 이름과 일치하는 자료를 확인해 **자료 남기기 / 백업 후 삭제**를 선택할 수 있습니다. 이름이 같은 방이 여럿이면 캐릭터와 방을 직접 고르세요. 이미 삭제한 방은 **방 자료 삭제…**에서 찾습니다. 전체 이야기를 정리하려면 기존 **이야기 연결 → 이야기 정리**에서 연결된 방을 확인하세요.

정리하는 동안 확인한 사용처를 재사용해 같은 자료를 반복해서 읽는 시간을 줄였습니다. 정리 도중 새 저장 요청이 오면 멈췄다가, 변경된 자료의 사용처를 다시 확인하고 이어갑니다. 자동 정리는 최근 24시간의 조각을 잠시 보관하고, **지금 정리**는 이 대기 없이 사용처를 확인합니다. 최근 완료 작업의 재시도 자료와 정상적으로 이어 쓸 수 있는 업로드는 보호합니다. 더 이상 저장할 수 없는 이전 작업은 정리하고, 미완료 업로드는 마지막 활동에서 7일이 지나면 만료됩니다. 사용 중인 자료나 백업이 손상되어 안전한 삭제를 확인할 수 없으면 이유를 표시하고 파일 삭제를 보류합니다.

백업은 정리 대상과 별도로 보관합니다. 필요 없는 백업은 백업 목록의 **삭제**로 지우세요. 정리는 기존 기능의 데이터를 초기화하거나 인물 파일을 자동 삭제하는 기능이 아닙니다.

확장 화면을 이전 버전으로 되돌리더라도 **서버 플러그인은 0.10.0 이상을 유지**하세요. 독립 백업을 옛 플러그인에서 직접 읽을 수는 없습니다. 저장 형식이 매우 오래된 화면으로 돌아가야 한다면 [저장 호환 복귀판](https://github.com/bongbong11/Scene_Reader_Hub/tree/v0.1.19-storage2-recovery)을 사용하세요.

## 화면과 오류 확인

창 오른쪽 아래 손잡이를 끌어 크기를 바꿉니다. 모바일에서도 사용할 수 있으며, 두 번 누르면 기본 크기로 돌아갑니다. 크기는 현재 브라우저에 저장됩니다.

상단 로그 복사 옆 **원형 상태 버튼**을 누르면 **실제 주입**과 **연속성 추론**을 따로 확인할 수 있습니다.

- **실제 주입 — 확인됨**: 주입문이 실제 전송 요청에 포함됐습니다. 모델 답변에 반영됐다는 뜻은 아닙니다.
- **연속성 추론 — 실행 전 / 실행 중 / 실행 완료**: 이번 판독 이후의 분석 실행 상태입니다. 실행 전은 오류가 아니며, 기능을 껐으면 **사용 안 함**, 도중에 취소됐으면 **중단**으로 표시합니다.
- 오류가 나면 연결모델·응답 확인·저장·확장 처리 중 확인된 원인만 짧게 표시합니다. 원인을 구분할 수 없으면 **원인 확인 필요**로 표시합니다. 자세한 분석 결과는 아래 **연속성 추론**에서 확인하세요.

정상적인 내부 검사 내역과 감정 수집·연결 시험 결과는 이 화면에 나열하지 않습니다. 검색·저장·주입 등에 실제 문제가 있으면 해당 오류는 함께 표시합니다. 상태는 현재 접속에서 확인한 기록이며 새 판독이나 방 이동 시 갱신됩니다. 빨강은 확인할 오류, 초록은 이번 요청의 주입 확인, 회색은 확인 전입니다. 끼끼는 확장 창을 여는 버튼이며, 상세 상태는 원형 버튼에서 확인하세요.

롤플용 연결 프로필과 확장용 연결 프로필은 별개입니다. 다른 롤플 프로필을 수정하거나 삭제해도 확장 분석을 취소하지 않습니다. **인물 분석을 매크로로 전달**을 켰다면 실제 요청의 매크로 위치를 사용하고, 매크로가 없으면 기존 통합 주입으로 전달합니다. 지정한 프리셋 주입 위치를 찾지 못하면 확인 안내가 표시됩니다.

**전체 진단 로그 복사**는 현재 탭과 관계없이 최근 실행과 마지막 실패를 복사합니다. 대화 원문·키·주입문 전문은 포함하지 않습니다. 새로고침하면 실행 기록이 사라질 수 있으므로 문제 직후 복사하세요. 자세한 실행 흐름은 개발자 모드에서 볼 수 있습니다.

연속성 오류는 **모델 요청 / 응답 해석 / 저장** 등 실패한 단계와 이유를 아래 **연속성 추론**에 표시합니다. 전체 로그에는 최근 분석 6회의 처리 결과와 마지막 오류, 요청·응답 크기와 출력 한도, 읽지 못한 필드 이름이 남습니다. 저장된 분석 오류 기록은 새로고침 후에도 확인할 수 있습니다. 오류 기록 자체도 저장하지 못한 경우에는 별도로 안내하므로 새로고침 전에 로그를 복사하세요. 이전 버전에 원인이 남아 있지 않은 오류는 **원인 기록 없음**으로 표시합니다.

브라우저 개발자 도구의 콘솔에는 문제가 있을 때 **연결 / 분석 / 주입 / 저장·설정**으로 묶어 기능·단계·오류 코드·담당 파일을 짧게 표시합니다. 같은 실행에서 같은 원인은 반복 표시를 줄입니다. 정상 대기나 취소는 오류로 출력하지 않으며 API 키·대화 원문·주입 전문은 넣지 않습니다.

| 증상 | 먼저 확인할 것 |
| --- | --- |
| 확장 아이콘이 안 보임 | 새로고침, 확장 활성화, 채팅창 아이콘 표시 설정 |
| 404 오류 | 서버 플러그인 폴더 위치와 `enableServerPlugins`, 서버 재시작 여부 |
| 401·403 오류 | 해당 서비스의 키·계정 권한과 연결 확인 결과. 키 원문은 공유하지 마세요. |
| 시간 초과·502 | 해당 서비스 연결 확인 후 재시도. 상태 버튼과 로그로 실패한 단계를 확인하세요. |
| 임베딩 실패 | 임베딩 서비스 선택과 인증 확인 후 상단 임베딩 재시도 |
| 인물 JSON 저장 실패 | 팝업의 오류 안내와 오류 로그 복사. 필수 항목 누락·잘린 파일 여부 |
| 인물 기록이 선택되지 않음 | 이번 턴 인물 판정의 참여·검색·길이 제한 등 제외 이유 |
| 판독했지만 주입이 안 보임 | 전체 사용 여부, 주입 위치의 기준 항목, 실제 요청 포함 상태 |
| 감정값이 없음 | 수집 방식·연결 프로필·참여 인물 확인 후 빠진 감정 수집 |
| NPC가 속마음만 보이고 행동하지 않음 | 사건 담당 인물과 요청 포함 상태, 다음 판독의 실제 행동 확인 결과 |

OOC만 있는 입력은 판독·주입을 건너뜁니다. 문의할 때는 문제 상황과 확장 안에서 복사한 로그를 알려 주세요. 서비스가 세부 오류를 전달하지 않은 경우에는 로그만으로 원인을 확정할 수 없습니다.

## 빠른 답장용 슬래시 명령어

빠른 답장 내용에 아래 명령어를 넣으세요. 명령 실행만으로 채팅 메시지를 자동 전송하지 않습니다.

| 명령어 | 동작 |
| --- | --- |
| `/srh-open` | 확장 창 열기 |
| `/srh-judge` | 지금 판독 실행. 판독·저장·주입 준비 완료까지 대기 |
| `/srh-auto on` / `/srh-auto off` | 생성 직전 자동 판독 켜기·끄기 |
| `/srh-enabled on` / `/srh-enabled off` | 확장 전체 판독·주입 켜기·끄기 |
| `/srh-clear` | 현재 Hub 판독 취소와 주입 해제. 저장 자료 유지 |
| `/srh-status` | 실행 상태를 JSON으로 반환 |

자동 판독·전체 사용 명령은 `toggle`로 전환하거나 인수를 생략해 현재 값을 확인할 수 있습니다. 알림으로 상태를 보려면 `/srh-status | /echo {{pipe}}`를 사용하세요.

`/srh-judge`는 입력창이 `/`로 시작하면 명령문을 RP로 읽지 않고 저장된 대화를 판독합니다. `/srh-clear`는 한 번만 해제하므로 다음 생성에서 다시 주입될 수 있습니다. 계속 중단하려면 `/srh-enabled off`를 사용하세요.
